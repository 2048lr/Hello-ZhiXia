# 文档

## 这个目录是怎么来的

源码注释里引用了大量设计文档 —— `data-model.md`、`ADR-0001` ~ `ADR-0014`、
`open-questions #7/#8/#9` —— 但**这些文档此前不在仓库里**。结果是每一处
「为什么这么做」都挂在一个打不开的编号上：对新人、对未来的自己都是死链接。

这个目录是**从代码注释反推重建**的索引，只解决一件事：**让那些引用可点、可查、可追溯**。

> ⚠️ **它不是原始设计文档。** 原始 ADR 里的备选方案、被否决的理由、当时的权衡过程与
> 讨论上下文都不在代码注释里，因此也不在这里。请作者用原始文档替换本目录。
> 在那之前，一个标注了出处、承认自己边界的索引，比一个悬空编号有用。

目录里还有一类**性质不同**的内容：本次代码审查新识别、源码注释中原本没有记录的缺口
（目前只有 [`open-questions.md`](./open-questions.md) 的第二部分）。
它们不是重建，已在文件内与重建内容分开标注 —— 混在一起会让「作者说过」和
「审查者认为」变得无法区分。

## 这个目录遵守的约定

1. **每一条都标注出处** —— 从哪个文件的哪段注释得来，便于核对与纠正。
2. **不知道就写不知道** —— 代码注释里没提到的编号（ADR-0002、ADR-0007）明确标为「未知」，
   **不猜测、不占号、不编内容**。
3. **以源码为准** —— 本目录与源码注释冲突时，以源码注释为准，并欢迎提 PR 修正本目录。
4. **区分「重建」与「新提出」** —— 凡是本次审查新提出、源码注释中原本没有的内容，
   一律单独成节并明确标注，**绝不与重建内容混排**。
