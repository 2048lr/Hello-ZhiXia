# Android 端

**目前是空骨架，尚未实现。**

## 决策已定

Android 定位为**瘦客户端 + 本地完整数据副本**（ADR-0006）：

- ✅ 持有完整的结构化数据副本（笔记、日程、待办、会话记录）
- ✅ 可离线读写本地数据，无需任何节点在线
- ✅ 可接收与触发提醒（走系统级闹钟，不依赖 agent 常驻）
- ✅ 可发起对话请求（需要算力节点在线）
- ❌ **不执行 agent**，不运行 pi

## 技术选型未定

「Android 是瘦客户端」已经定了，但**用什么技术实现还没定**：

| 候选 | 说明 |
| --- | --- |
| Capacitor | Web 技术栈，可与 `@hzx/ui-shared` 最大程度复用；需验证后台闹钟与通知能力 |
| React Native | 生态成熟，但 UI 层无法复用 `@hzx/ui-shared` |
| 原生 Kotlin | 对 `AlarmManager`、`Keystore`、后台限制的控制最直接 |

**选型的关键判据是闹钟可靠性。** ADR-0011 把提醒的投递下放给了本地系统闹钟，
如果所选方案无法可靠地注册系统级闹钟（或被系统抑制），整个提醒功能就不可靠 ——
而提醒是日常助手的核心功能。

## 为什么不在 Android 上跑 pi

pi 需要 Node.js ≥ 22.19。Android 上内置 Node（`nodejs-mobile`）技术上可行，
但**即使内置了也解决不了根本问题**：Doze 模式与各厂商的杀后台策略会让常驻进程无法存活。
结果是「算力节点」名不副实，却要付出明显的维护成本。详见 ADR-0006。

## 数据层并不因此简化

瘦客户端指的是**不跑 agent**，不是**不参与同步**。Android 端仍需完整实现
op log、CRDT 合并、墓碑等机制，因此它直接依赖 `@hzx/core-sync` ——
这正是 ADR-0010 坚持「数据层第一天就共享」的原因。
